# Provenance: Dataset Evidence v1 (`01_official_dataset_evidence.ipynb`)

Короткая audit-заметка. Фиксирует расхождение между историческими
метаданными Dataset Evidence v1 и notebook, реально замороженным в git.
Научные выводы notebook этой заметкой не меняются.

## Главное

**Тег `dataset-evidence-v1` НЕ указывает на notebook с SHA-256 `9eb2c78b…`.**
В теге заморожена другая, укороченная версия (`7f847db5…`). Ниже — что
известно точно и что остаётся непроверенным.

## 3. Сравнение с восстановленным `9eb2…`

Файл с SHA-256 ровно `9eb2c78b…` сохранился **вне репозитория** — во
временном scratchpad сессии, которая его создала
(`/tmp/.../scratchpad/01_official_dataset_evidence.microfix.executed.ipynb`).
В git object database его нет. Это не долговременное хранилище: `/tmp` может
быть очищен. Сравнение выполнено 2026-09-25 и дало следующее:

- 92 ячейки frozen-версии **совпадают по source и типу** с первыми 92
  ячейками `9eb2…` (последовательность ячеек выровнена через diff), с теми же
  cell ID и теми же execution_count. Metadata notebook идентична.
- В frozen-версии **отсутствуют ровно 2 последние ячейки** `9eb2…`:
  - markdown `043d3ba5413b4a27` «Итоговая самопроверка notebook»
    (sha256 source `2efe63c3…3df9`);
  - code `ea6dde8fe83b4c20` — явная самопроверка
    (sha256 source `8c7a73d2…21ad9`):

    ```python
    assert "target_delay_s" not in validate_points.columns
    assert "target_class" not in validate_points.columns
    assert "time_fact_begin" not in validate_points.columns
    assert "time_fact_begin" not in validate_schedule_plan.columns
    ```

    плюс `print` с итоговой формулировкой.
- Отличия outputs в совпадающих ячейках объясняются повторным выполнением:
  1 строка времени в ячейке fingerprint (`0.21 c` → `0.27 c`) и байты PNG в
  15 ячейках с фигурами. Все остальные текстовые outputs, включая все
  числовые результаты, идентичны.

## 4. Что известно и что не проверено

Известно (доказано сравнением):

- все научные выводы, таблицы и числа frozen-версии совпадают с `9eb2…`;
- различие — только удалённая финальная самопроверка и шум повторного
  выполнения.

Не проверено:

- кто, когда и зачем удалил 2 ячейки. Это произошло до единственного
  коммита, и в истории git следов нет;
- что frozen-outputs получены чистым перезапуском kernel. Последовательные
  execution_count `1..48` с этим согласуются, но не доказывают его.

## 5. Следствие для чтения frozen-notebook

В frozen-версии остаются ссылки на отсутствующую «финальную ячейку /
финальную проверку»: ячейки 0, 8, 45 и 90 (Evidence Register, строка
«Скрытый target `validate` … См. финальную проверку ниже»).

**В замороженном артефакте эта явная assert-проверка не выполнялась.**
Гарантия «hidden validate target не вычислялся» в frozen-версии опирается на
обоснование в §9.4 и на код notebook, а не на выполненную финальную
assert-ячейку. Сама проверка тривиально истинна для кода frozen-notebook:
ни одна ячейка не добавляет эти колонки в `validate_points` или
`validate_schedule_plan`. Но это вывод из чтения кода, а не выполненная
проверка.

## 6. Что сделано и чего не сделано

- История git не переписывалась, тег `dataset-evidence-v1` не перемещался.
- Notebook не изменялся, не заменялся и не воссоздавался.
- Если канонической должна считаться полная версия `9eb2…`, это отдельное
  решение команды: например, новый тег поверх нового коммита. Не
  переписывание существующего.

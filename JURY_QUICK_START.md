# Инструкция для жюри

## Быстрый запуск

Для проверки решения нужны:

- **Docker Desktop** (Windows / WSL) или **Docker + Docker Compose** (Linux);
- предоставленный организаторами образ эмулятора `ndtp-telemetry-emulator.tar`;
- API-ключ Яндекс Карт для отображения карты.

Python, Node.js, PostgreSQL и зависимости проекта отдельно устанавливать не требуется — всё приложение собирается и запускается через Docker Compose.

> **Важно:** образ NDTP-эмулятора и исходный организаторский датасет не публикуются в репозитории.

---

## 1. Клонировать репозиторий

```bash
git clone https://github.com/FierceZymotic/mostransport.git
cd mostransport
```

---

## 2. Настроить Яндекс Карты

Если `.env` отсутствует:

```bash
cp .env.example .env
```

В `.env` указать:

```env
VITE_YANDEX_MAPS_API_KEY=<YOUR_YANDEX_MAPS_API_KEY>
```

Без этого ключа Backend, ML, realtime-поток и dashboard работают, но картографическая подложка Яндекс Карт не загружается.

Если ключ был добавлен уже после первой сборки frontend, пересоберите его:

```bash
docker compose up -d --build frontend
```

---

## 3. Запустить решение

### Linux / WSL

Если образ эмулятора ещё не загружен в Docker:

```bash
EMULATOR_TAR="/path/to/ndtp-telemetry-emulator.tar" ./run-demo.sh
```

Если образ уже загружен:

```bash
./run-demo.sh
```

### Windows PowerShell

Если образ эмулятора ещё не загружен:

```powershell
$env:EMULATOR_TAR="C:\path\to\ndtp-telemetry-emulator.tar"
.\run-demo.ps1
```

Если образ уже загружен:

```powershell
.\run-demo.ps1
```

Альтернативно образ можно загрузить вручную один раз:

```bash
docker load -i /path/to/ndtp-telemetry-emulator.tar
```

После этого `EMULATOR_TAR` повторно указывать не требуется.

---

## 4. Что делает launcher

`run-demo.sh` / `run-demo.ps1`:

1. проверяет Docker и Docker Compose;
2. проверяет конфигурацию и runtime-артефакт ML-модели;
3. при необходимости загружает образ NDTP-эмулятора из `EMULATOR_TAR`;
4. собирает и запускает PostgreSQL, ML service, Backend, frontend и NDTP-эмулятор;
5. ждёт готовности сервисов;
6. выводит адрес dashboard;
7. пытается открыть dashboard в браузере автоматически.

Первый запуск может занять несколько минут из-за загрузки базовых Docker-образов и сборки контейнеров.

---

## 5. Что происходит в системе

Основной демонстрационный поток:

```text
NDTP emulator
→ Backend
→ VehicleState / telemetry history
→ trip / schedule context
→ ML service
→ prediction
→ PostgreSQL + WebSocket
→ dashboard
```

На dashboard в realtime обновляются координаты, скорость и свежесть телеметрии. Если для транспортного средства доступен необходимый контекст расписания, отображается прогноз задержки на горизонте **10–15 минут**, уровень риска и причина/предупреждение.

### Важно о demo-эмуляторе

Стандартная конфигурация эмулятора создаёт синтетические ТС `1001–1004` со случайно генерируемой телеметрией. Для таких объектов Backend не всегда может достоверно сопоставить координаты с реальным рейсом из reference-данных.

Поэтому для отдельных ТС нормальным результатом является:

```text
маршрут недоступен
прогноз: нет данных
```

Это не ошибка dashboard: система сознательно не подставляет фиктивный `trId` и не вызывает ML без достоверного контекста рейса.

---

## 6. Где смотреть результат

После запуска откройте URL dashboard, который напечатает launcher.

На dashboard доступны:

- карта и realtime-положение ТС;
- список транспортных средств;
- скорость и свежесть телеметрии;
- маршрут/рейс, если он достоверно определён;
- прогноз задержки;
- уровень риска;
- причина или degraded-warning;
- история последних прогнозов / alerts.

Техническое состояние

```text
degraded:current_deviation_unavailable(no_fact_source)
```

означает, что прогноз рассчитан без фактического текущего отклонения от расписания. В интерфейсе оно отображается как предупреждение:

```text
Недостаточно фактических данных по графику
```

Это не ошибка ML-прогноза.

## 7. Метрики ML

Финальная модель: **HistGradientBoostingRegressor**

Runtime feature schema: `runtime-safe-v1`

Количество признаков: **29**

Offline-валидация:

```text
GroupKFold OOF MAE = 77.34 с
```

Целевая величина: `delay_seconds`

Горизонт прогнозирования: **10–15 минут**

---

## 8. Остановка

```bash
docker compose down
```

Volumes с данными по умолчанию не удаляются.
